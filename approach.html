Approach

A model may propose. Only a rule may decide.

Most clinical AI fails not because the model is weak, but because nobody can say why it said what it said, or what happens when it is wrong. We started from the failure mode.

Order of authority

The order is not negotiable, and it is enforced by construction.

Deterministic engine

Guideline thresholds in a configuration file a clinician edits directly — NEWS2, qSOFA, shock index, CTAS patterns, STEMI criteria. Every finding names its criterion. No model runs here.

Model ensemble

Independent readers, fused by per-finding weights fitted to each model's measured strengths. Never by majority vote — a vote averages away exactly the disagreement a clinician needs to see.

Human gate

Nothing is finalised without a signature. No auto-send, no auto-sign, no confidence threshold that bypasses it. The clinician's rating trains the next version.

The guardrail runs after the models, on every case, and moves patients in one direction only. There is no code path in which a model output, at any confidence, lowers a band a rule has set.

Uncertainty

Refusing to answer is a feature.

Input quality
A standard ECG printout prints lead II twice. Comparing the two digitisations tells us whether the scan can be trusted; when it cannot, the system declines to interpret.
Missing data
A blank vital is reported as missing, never scored as normal. It lowers the stated confidence and the clinician sees which inputs were absent.
Confidence
Our chest figure is an ensemble-agreement score, and the interface says so. Calling it a probability would be a lie with a decimal point.
Self-report
We never ask a model how sure it is. The answer is fluent, plausible and badly calibrated — worse than no number, because it is actionable and wrong.
Poor signal
Low input quality caps the tier. The system may say it cannot tell. It may not say a patient is fine on the strength of a bad recording.
Evaluation

Under-triage is the metric. Accuracy is not.

A triage system that is 95% accurate and misses the arrest is a failed system. We gate on the direction of the error, not its rate.

  • Synthetic self-test — cases with known answers through the whole chain, before anything else runs
  • Label and fold checks — including proof that validation folds are genuinely disjoint
  • Corpus agreement — agreement and under-triage reported separately, never merged
  • External validation — held-back data from a different population and machine estate
  • Shadow mode — running live beside clinicians who cannot see our output

Ported logic is proved, not trusted: the browser rule engine is verified against the Python original on every case in the corpus, as part of the test suite.

Deployment

Patient data does not leave the clinic to be useful.

Clinic LAN
The imaging archive with full identifiers, the folder-watch agent, and the radiologist's browser. No internet needed to view or report a study.
Our GPU
Inference only, transient and in memory. No identifiers, nothing written per case.
Cloud
Worklist, reports and audit, keyed on a study UID and a pseudonym. No name, no patient ID, no accession number.

The name is on the screen but not in the database. The browser asks the clinic's own archive over the LAN and merges names in memory. Search works in reverse — the cloud only ever filters on opaque identifiers.

Limits

Things we will not build.

Autonomous decisions

No output is finalised or acted on without a named clinician signing it. There is no threshold at which that step is skipped.

Model-decided drug safety

Allergy, interaction, dose and duplicate checks are rule engines. A model may draft. It may never clear a prescription.

Diagnoses to patients

Patient-facing triage returns a specialty and an urgency. Never a diagnosis, and never a medication.

Silent substitution

Substituting a prescribed drug requires an explicit approval event with an actor identity. It never happens automatically.

Unmeasured claims

No performance figure appears anywhere unless we can name the dataset and the system version that produced it.

Data as leverage

Data is used for the consented purpose, in the region it was collected. It is not the business model.
